间距与对齐：用空白说话

间距不是"留点空，好看一点"。它在告诉用户哪些东西是一伙的；对齐在告诉用户东西是按什么规矩摆的。这一课讲清这两件事，再讲一个手机上特有的问题：按钮要多大，手指才点得准。

约 25 分钟 · 纯讲解

01靠得近的，就是一伙的

心理学里有一条叫"接近性"的格式塔原则：靠得近的东西，会被看成一组。尼尔森诺曼集团（NN/g）的文章还指出，接近性的力量强到能压过颜色、形状上的相似。下面这排圆点，颜色是蓝橙交替的，但你一眼看到的是"三组"，而不是"蓝的一类、橙的一类"：

苹果 HIG 的布局一章也是这个意思："把相关的东西放在一组"，并给了三种分组工具：留白、容器（卡片、背景块）、分割线。

02间距从一张短清单里挑：8pt 网格

第 1 课说过，"好看"的第一层答案是有规律：字号、颜色、间距都只从一张短清单里挑。间距的清单，业内最常见的是 8 的倍数，叫"8pt 网格"（安卓叫 8dp）：

出处怎么规定的
Material Design（谷歌）2014 年第一版就写明"所有组件对齐 8dp 的方形网格"，工具栏图标这类小东西对齐 4dp 网格。官方
Ant Design（蚂蚁）"网格的基数为 8"；页面上下方向的间距分小、中、大三档：8、16、24，不够用就按 8 的倍数加。官方
Apple HIG没有规定网格。iOS 自己的尺寸也不全是 8 的倍数：导航栏 44pt、底部安全区 34pt、正文 17pt。HIG 只在无障碍一章给了控件周围的建议留白（见第 06 节）。

为什么偏偏是 8？常见的解释是：8 能被 2 连续整除三次，在 1.5 倍、2 倍、3 倍的屏幕上换算成物理像素都是整数（8 × 1.5 = 12），不会出现半个像素的模糊边。需要更细的时候用 4。常见解释

但要记住重点：网格的价值不在"8"这个数，而在"只从清单里挑"。苹果没用 8pt 网格，界面照样整齐，因为它的尺寸同样是一套固定的数。下面两张商品卡，差别只在间距，打开"显示间距"看看：

左边的问题不只是"数字不整"。标题和副标题隔了 14，副标题和价格却只隔 6，于是副标题看起来和价格是一伙的，接近性讲错了关系。右边的数字有规律：4 = 同一件事的两行，12 = 相邻的不同信息，16 = 隔开操作区。每个数都能说出理由，这就是"有规律"。

03内小外大

上一节已经出现了一条规律，业内常把它写成"内部间距 ≤ 外部间距"：一个整体里面的空白，要小于它和外面其他东西之间的空白，否则它会"散架"，或者和邻居"粘"在一起。这是经验法则，不是哪家的正式标准，但它就是接近性原则的直接推论。最常见的两个场景：

场景一：分组标题

分组标题属于它下面的内容，所以它离下面要近，离上一组要远。左边上下一样远，标题像是夹在两组中间：

iOS"设置"里的分组列表就是右边这样：分组标题紧贴在它那组上方，组和组之间留一大段空。网页文章也一样，h2 的上边距通常明显大于下边距。

场景二：图标和它的文字

图标配文字是一个整体。图标和文字之间的距离，必须小于这一对和下一对之间的距离：

内外一样宽"128"是谁的？
128 36 分享
内 4、外 24三对一目了然
128 36 分享

先用留白，再考虑线：HIG 列出的三种分组工具里，留白最轻。MIT 的界面设计课有一节就叫"留白避免视觉噪声"，举的是信息设计大师 Tufte 的例子：去掉柱状图上的格线，改用空白来示意。所以分组时先试试拉开间距；间距不够用，再加卡片背景或分割线。

04对齐：边缘越少越整齐

HIG 对对齐的说法是："对齐让界面整洁有序，方便视线扫描。人们会认为对齐的东西彼此相关，缩进的东西从属于它上面那一项。"

MIT 的界面设计课总结得更短："对齐的位置越少，设计越简单。"每多一条不同的边缘，眼睛就要多找一次起点。下面两张订单卡内容一样，打开"显示对齐线"，橙色虚线是每个元素的左边缘，数一数各有几条：

左边缘条数由浏览器现场量出各元素的左边位置算得（相差 1px 以内算同一条）。

右边只有两条边：店名、缩略图、按钮共用最左边的一条；商品名和说明共用缩略图右边的一条，这条"缩进"正好表达了"这两行是在描述这件商品"。左边多出来的边，每一条都是随手偏了几个像素造成的，没有表达任何意思。

居中也是一种对齐。左边的按钮单独居中，就又多了一条"中线"。按钮可以居中，但要有理由，比如整张卡片的内容都是居中排的。

05表格里的对齐：文字靠左，数字靠右

表格和列表是对齐最见功力的地方。设计师 Matthew Ström 在《Design better data tables》里给的头两条规则是：

  • 数字靠右对齐。比较数字大小是从个位开始对的，靠右能让个位、十位、百位上下对齐，一眼看出谁大。前提是小数位数一致。
  • 文字靠左对齐，和阅读方向一致。
  • 表头跟着这一列的对齐方式走；数字再配上等宽数字（第 2 课讲过）。

例外：日期、手机号、订单号这类"不比大小"的数字，靠左靠右都可以。iOS 的列表也遵循同样的逻辑：左边是名称，右边是当前的值，"设置"里大多数行都是这样排的。第 5 课的网页后台订单表里金额靠右，也是这个原因。

06可点区域：看起来小，点起来要大

手机上的间距还有一个硬约束：手指比鼠标粗。按钮太小、挨得太近，就会点错。各家的数字：

出处可点区域说明
Apple HIG（iOS）44 × 44 pt
最小 28 × 28 pt		无障碍一章：默认 44、最小 28；按钮一章："点击区域至少 44 × 44 pt"
Material Design48 × 48 dp约合 9 毫米，"无论屏幕多大"
WCAG 2.2 · 2.5.8（AA）24 × 24 CSS px网页的最低线；更小的目标必须彼此离得够远
WCAG 2.2 · 2.5.5（AAA）44 × 44 CSS px增强级，W3C 建议重要按钮尽量做到

HIG 还特别说明：控件之间的间距和尺寸一样重要。有边框、有底板的控件，周围留约 12pt；没有边框的（比如纯图标、纯文字按钮），可见边缘周围留约 24pt。

关键在于：可点区域不等于看得见的大小。导航栏上的图标只有二十来 pt，但它的可点区域应该是 44 × 44。打开"显示可点区域"对比：

对写代码的意义：用系统的导航栏、工具栏按钮，可点区域系统已经处理好了。自己画的小按钮，要把点击范围撑大，而不是把图标放大：

// SwiftUI：图标保持原大小，点击范围撑到 44 × 44
Button(action: share) {
    Image(systemName: "square.and.arrow.up")
        .frame(minWidth: 44, minHeight: 44)
        .contentShape(Rectangle())   // 空白处也算点中
}

/* 网页：用 padding 或最小尺寸撑大，而不是放大图标 */
.icon-btn {
  min-width: 44px;
  min-height: 44px;
  display: inline-grid;
  place-items: center;   /* 图标在区域里居中 */
}

07iOS 的边距和安全区：交给系统

第 1 课画过 iPhone 页面的骨架：顶部安全区、左右边距、底部安全区。这些数字有一个共同点：不要写死，让系统给。

  • 安全区：HIG 的定义是"窗口里没被硬件或其他视图遮住的区域"，比如灵动岛、状态栏、标签栏、底部横条。内容和按钮要放在安全区里；背景色、背景图可以铺满整屏。SwiftUI 默认就把内容排在安全区内，背景要铺满时用 .ignoresSafeArea()。
  • 左右边距：UIKit 会给页面的根视图强制一个"最小边距"，但苹果文档没有写成固定数字，只说可以从 systemMinimumLayoutMargins 读到。实测在 iPhone 上一般是 16 或 20pt，随机型变化。实测值
  • SwiftUI 的 .padding()：不写数字时，官方文档说用的是"随平台而定的默认值"，iPhone 上常见是 16pt。需要精确时写明数字。
  • 正文限宽：HIG 提到系统有专门的布局参考线，用来"限制文字宽度以便阅读"（UIKit 里叫 readableContentGuide），在 iPad 这种宽屏上尤其有用，和第 2 课讲的行宽是一回事。

网页没有系统替你管边距，要自己定：手机上左右留 16px 左右是常见做法经验，宽屏上用 max-width 把内容收在中间。

08本课要点

  • 间距表达关系：靠得近的会被看成一组（接近性），它的力量能压过颜色和形状。组内紧、组间松。
  • 间距从固定清单里挑。最常见的是 8 的倍数（Material 8dp，Ant Design 8 / 16 / 24），细处用 4。苹果没规定网格，关键是"有规律"而不是"8"。
  • 内部间距 ≤ 外部间距：分组标题离自己的内容近、离上一组远；图标离自己的文字近、离下一对远。
  • 分组先用留白，不够再加容器（卡片、背景）或分割线。
  • 对齐的边缘越少越整齐；缩进表示从属；居中也算一条对齐线。
  • 表格里文字靠左、数字靠右，表头跟随列；数字用等宽数字。
  • 可点区域：iOS 44 × 44pt（最小 28），Material 48dp，网页至少 24px（AA），重要按钮 44px。可点区域可以比图标大。
  • 安全区、系统边距交给系统，不写死数字。
