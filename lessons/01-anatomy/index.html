认识界面：它是由什么组成的

先不谈好不好看。这一课只做一件事：把一个界面拆开，认清里面有哪些零件、用什么单位。后面每一课，讲的都是其中一种零件。

约 15 分钟 · 纯讲解

01界面只做两件事

不管是 App 还是网页，界面上的每个元素都在做下面两件事之一：

  • 传达信息：文字、数字、图片，告诉用户"现在是什么情况"。
  • 提供操作：按钮、输入框、可以点的列表行，让用户"做点什么"。

我们说一个 UI "好"，第一层意思是：信息一眼就能看懂，操作一下就能找到、不会点错。第二层才是"看着舒服"。

"看着舒服"听起来很玄，其实大部分来自一套可以讲清楚的规律。这门课就是把这些规律一条条讲给你。

02单位：pt 是什么

写 UI 时用到的数字，比如字号 17、边距 16、按钮高 44，单位都不是屏幕的物理像素，而是一种逻辑单位：

  • iOS 叫 pt（point，点）
  • Android 叫 dp
  • 网页叫 CSS px

三个名字，同一个意思：一个和屏幕清晰度无关的尺寸单位。

为什么需要它？因为不同手机屏幕的像素密度不一样。iPhone 16 的屏幕实际有 1179 × 2556 个像素，按 3 倍密度（写作 @3x）换算，逻辑尺寸是 393 × 852 pt。同一个 44pt 的按钮，在 2 倍屏上占 88 个像素，在 3 倍屏上占 132 个像素，人眼看起来一样大。

@1x1pt = 1 个像素
（早期非 Retina 屏）
@2x1pt = 2 × 2 个像素
@3x1pt = 3 × 3 个像素
（现在大多数 iPhone）

对写代码的意义：SwiftUI 里 .padding(16)、.font(.system(size: 17)) 的数字就是 pt；CSS 里的 16px 也是逻辑像素。所以规范里看到的数字，可以直接写进代码，不用换算。

这门课里所有手机示例，用的都是 393 × 852 pt 的画布（iPhone 15 / 16 的逻辑尺寸），1 个 CSS px 就代表 1pt。

  • 左右边距：16pt内容离屏幕边缘的距离，系统默认 16pt（大屏机型是 20pt）。几乎所有内容都对齐这两条线。
  • 标签栏：49pt底部的 3～5 个主入口。iOS 26 起它变成了悬浮的玻璃胶囊样式，但位置和作用没变。
  • 底部安全区：34ptHome 指示条那一条，同样不放内容和按钮。

剩下中间那块，才是真正放内容的地方。iOS 系统控件（导航栏、标签栏）会自动处理这些区域；自己画界面时，要记得给安全区留出位置。

网页呢？

网页没有系统规定的骨架，但最常见的结构是这样的（数字是常见做法，不是标准）：

顶栏　约 56～64px 高
侧边导航
约 200～260px 宽
内容区
限制最大宽度（比如 1200px）并居中，
屏幕再宽，内容也不会无限拉长

文字

界面上大部分信息靠文字传达。控制文字的只有四个变量：字号（多大）、字重（多粗）、颜色（多深）、行高（行与行之间的距离）。

字号
只有 4 种：28 / 20 / 17 / 15 pt
字重
3 种：常规、半粗（标题、按钮、实付金额）、粗（"运输中"）
颜色
3 种：黑色主文字、灰色次要文字、蓝色可点击文字（另有按钮上的白字）

第 2 课细讲：为什么 iOS 正文是 17pt，字号怎么分级。

颜色

左边现在被去掉了颜色，只剩明暗。你会发现页面几乎没变，只有原来蓝色的几处（按钮、进度条、左上角返回、右上角更多）变成了灰：这个页面只有一种彩色，其余全是黑白灰。

背景 #F2F2F7 卡片 #FFFFFF 主文字 #000000 次要文字 #6E6E73 强调色 #0066CC

界面里的颜色一般分三类：中性色（黑白灰，占绝大部分面积）、强调色（通常是品牌色，用在可以点的地方）、语义色（红色表示错误或危险，绿色表示成功，等等）。

第 3 课细讲：灰色为什么要分几级，对比度怎么算。

间距

元素之间的空白。它不是"空着没用"，而是在告诉用户哪些东西是一组：离得近的是一组，离得远的是两组。

左边：蓝色是块与块之间的距离（外边距），橙色是块内部的留白（内边距）。

页面左右边距
16pt
卡片之间
12pt
卡片内边距
上下 14pt，左右 16pt
两个按钮之间
10pt

第 4 课细讲：间距怎么取值（8pt 网格），怎么用间距分组。

形状

圆角、边框、分割线、阴影，决定元素的轮廓。规律是：同一类元素，形状保持一致，比如所有卡片都是同一个圆角。

图标与图片

图标是"不用读的文字"，图片往往就是内容本身。iOS 有一套官方图标库 SF Symbols，和系统字体配套设计：图标能跟着字号、字重一起变大变粗，放在文字旁边很协调。

组件

前面五种零件的固定组合，可以在很多页面里反复使用。拿写代码来类比：前五种是基本类型，组件就是封装好的函数。

这个页面里
导航栏、状态区（标题 + 说明 + 进度条）、卡片、列表行（左标签、右数值）、主按钮、次按钮

好的产品组件很少，但到处复用，所以整个 App 看起来"是一家人"。iOS 系统自带了大部分常用组件，直接用就能和系统保持一致。

第 6、7 课细讲：组件的各种状态，iOS 的导航结构。

左边的字号有 14、15、16、18、20，彼此只差一两号；颜色这里标红、那里标绿、那里标蓝。没有哪一处是"错"的，但整体就是让人觉得乱，又说不上为什么。原因就在这里：取值太多、太随意，眼睛找不到规律。

你可能注意到，左边的字重反而只有 1 种。那是因为它全部加粗了。所有字一样粗，等于没有用粗细来区分任何东西。所以种类少不一定是有规律，关键是每个取值有没有明确的用途。这一点第 5 课会细讲。

右边先定了一张很短的清单，所有地方都从清单里挑。写代码的人对这个很熟悉：左边像满屏的魔法数字，右边像先定义好常量、再到处引用：

// 右边这个页面的"常量表"
字号     = [28, 20, 17, 15]
字重     = [常规, 半粗, 粗]
文字颜色 = [主文字 #000000, 次要 #6E6E73, 强调 #0066CC]
间距     = [10, 12, 14, 16]
圆角     = [10, 14, 胶囊]

设计师把这类常量叫做 Design Token（设计令牌），一套 Token 加上用它搭出来的组件，就叫设计系统。

有了清单只是第一步。清单里该放哪些值（为什么正文是 17 而不是 16）、什么时候用哪个，就是后面每一课要讲的。另外，规律不是"美"的全部，品牌感、情绪这些更高层的东西要靠长期积累。这门课先把能讲清楚的部分讲清楚。

06小词典

后面会反复出现的词，先混个脸熟，不用记，用到时会再讲。

本课pt / dp / CSS px

逻辑像素，和屏幕清晰度无关的尺寸单位。

本课安全区

不会被灵动岛、Home 指示条挡住的区域，内容要放在这里面。

第 2 课字号

文字的大小。iOS 正文默认 17pt。

第 2 课字重

文字的粗细：常规（Regular）、中等（Medium）、半粗（Semibold）、粗（Bold）。

第 2 课行高

一行文字占的高度，决定行与行之间是松还是紧。

第 3 课对比度

文字和背景的明暗差。有正式标准：小字至少 4.5 : 1。

第 4 课内边距 / 外边距

元素内部的留白 / 元素和元素之间的距离。

第 5 课视觉层级

界面替用户排好的"先看什么、后看什么"。

第 6 课圆角

矩形四个角的弧度。同类元素保持一致。

第 6 课组件 / 状态

可复用的界面单元（按钮、列表行……）/ 它在不同时刻的样子（默认、按下、禁用、加载中……）。

第 7 课HIG

Human Interface Guidelines，苹果官方的《人机界面指南》，iOS 设计的标准答案。

本课Design Token / 设计系统

界面里所有取值的常量表 / Token 加上用它做出来的组件。
