颜色：用途、层级与对比度

颜色是最容易用乱的零件。这一课讲清三件事：颜色按用途分几类；同一类里怎么分层；怎么用"对比度"这把尺子量看不看得清。

约 25 分钟 · 纯讲解

01先学会描述一个颜色

屏幕上每个点都由红、绿、蓝三种光混出来，每种光的强度从 0 到 255。#0066CC 这种写法就是把三个数写成十六进制：红 00、绿 66、蓝 CC（即 0、102、204）。

但"红绿蓝各多少"不符合人的直觉。调颜色时更好用的是 HSL：色相（什么颜色，0～360°的色环）、饱和度（多鲜艳）、明度（多亮）。比如"同一个蓝，调深一点"，就是只改明度。

拖动下面的滑块试试。右边两个数字是这个颜色作为文字放在白底、黑底上的对比度，第 05 节会细讲。这里先留意一个反直觉的现象：把明度固定在 50%，只拖色相，黄色（60°）在白底上只有 1.07:1，蓝色（240°）却有 8.59:1。HSL 的"明度"只是数学上的值，不等于人眼感到的亮度，所以一个颜色看不看得清，不能凭 HSL 数值猜，要算对比度。

02颜色按用途分三类

界面里的每个颜色，都应该能回答"它是干什么用的"。按用途，基本只有三类：

中性色

黑、白、灰。背景、正文、分割线都用它，占界面绝大部分面积。好看的界面，大部分其实是灰的。

强调色

通常就是品牌色，只用在可以点的地方：按钮、链接、选中状态。一般只有一个。

语义色

颜色本身带含义：红色表示错误或危险，橙黄表示警告，绿色表示成功。只在需要表达这些含义时出现。

苹果 HIG 的第一条颜色原则就是：不要用同一个颜色表达不同的意思。HIG 举的例子是：如果你用品牌色表示"这个无边框按钮可以点"，那就别再用同样或相近的颜色去装饰不能点的文字，否则用户分不清哪些能点。

还有一点值得中国开发者注意，HIG 专门举过这个例子：颜色的含义因文化而异。苹果自己的"股市"App，英文版用绿色表示上涨，中文版用红色表示上涨。所以"红色 = 坏"并不是放之四海皆准，要看用户所在的环境。

到了 iOS 26 的 Liquid Glass（液态玻璃）界面，"强调色要少"写得更具体了。HIG 要求给玻璃材质上色要克制：主操作的强调色加在按钮背景上，而不是加在图标或文字上；不要给多个控件的背景都上色。系统自带的"完成"按钮就是这么做的：一排工具栏按钮里，只有它是蓝色的。

常听到的"60-30-10 法则"：主色占 60%、辅助色 30%、强调色 10%。它据说来自室内设计，但没人能给出确切出处，是个经验法则。真正有用的是背后的道理：强调色要少，到处都是就没人注意了，这和第 5 课讲的"先弱化再强调"是一回事。

03按用途命名，而不是按长相命名

写代码的人都知道，变量要按含义命名，不要按值命名。颜色也一样：叫它"次要文字色"，而不是"60% 的灰"。苹果的系统颜色就是这么设计的，HIG 把它们叫做动态系统颜色，"按用途而不是按外观来定义"：

前景（文字、线条）用途背景用途
label主要内容的文字systemBackground整个页面的底色
secondaryLabel次要内容的文字secondarySystemBackground页面里的分组
tertiaryLabel第三级文字tertiarySystemBackground分组里的再分组
quaternaryLabel第四级文字systemGroupedBackground 等分组列表用的一套背景
placeholderText输入框占位文字好处是：深色模式、"提高对比度"设置打开时，这些颜色会自动换成对应的版本，你一行代码都不用改。
separator分割线
link链接文字

出处：Apple HIG · Color（Platform considerations · iOS, iPadOS）。

HIG 对这套颜色有两条要求：

  • 不要改变它们的含义：比如不要拿分割线颜色当文字色，不要拿次要文字色当背景色。
  • 不要在代码里写死系统颜色的数值：文档里列出的色值"只供设计时参考，实际数值可能随版本变化"，要用 Color 这类 API 取用。

第二条刚发生过：HIG 的更新记录写着，2025 年 6 月"更新了系统颜色的数值"。iOS 的系统蓝在浅色模式下现在是 RGB(0, 136, 255)，也就是 #0088FF，不再是很多人背过的 #007AFF。代码里写死旧值的 App，颜色就和系统对不上了。

Material 3 的思路一样，叫颜色角色（color roles）：Primary、Surface、Error……而且每种底色都配一个"on 颜色"，专门用来放在它上面，比如 Primary 底上的文字用 OnPrimary。底色和文字色总是成对出现，对比度就不容易出问题。

对写代码的意义：SwiftUI 里用 .foregroundStyle(.secondary)、Color(.systemBackground) 这类语义写法；自定义颜色在 Xcode 的颜色集（Color Set）里同时提供浅色、深色版本。HIG 还建议给每个版本再配一个"提高对比度"的变体。

发现了什么：默认的浅色模式下，12 种颜色作为文字放在白底上，只有靛蓝达到小字要求的 4.5（为什么是 4.5，第 05 节细讲）。绿、橙、黄、薄荷、蓝绿、青只有 1.5～2.3，连系统蓝也只有 3.52。切到"浅色 · 提高对比度"，12 种全部变深、全部达标，而且大多落在 4.5 刚出头。从数字看，默认色板更看重鲜艳，达标的版本放在了"提高对比度"这个辅助功能设置里。

所以用系统颜色当小字的颜色，或者在它上面放白字时，要自己检查对比度。HIG 自己也说："Avoid using colors that make it hard to perceive content in your app."

05对比度：量"看不看得清"的尺子

"这个灰是不是太浅了"，以前只能凭感觉。对比度把它变成了一个数：用两个颜色的"相对亮度"相除，结果从 1:1（完全一样）到 21:1（纯黑配纯白）。这个公式来自无障碍标准 WCAG，是目前少有的、有明确数字的硬标准：

对象最低对比度级别说明
普通文字4.5 : 1AA（1.4.3）绝大多数界面文字
大字3 : 1AA（1.4.3）至少 18pt（约 24px），或 14pt 粗体（约 18.5px）
图标、输入框边框、焦点框3 : 1AA（1.4.11）理解界面必需的图形，和相邻颜色比
增强级文字7 : 1AAA（1.4.6）更高要求

不能点的（禁用状态的）控件、纯装饰、Logo 不受限制。苹果的说法和 WCAG 一致：HIG 的暗色模式一章写着，"对比度至少不低于 4.5:1；自定义的前景和背景色，争取做到 7:1，尤其是小字"。

06灰色要分几级

中性色里最常用的是文字灰。第 5 课讲层级时说过"把次要的调灰"，但灰也要成套、分级，而不是每处随手挑一个：

  • iOS：label、secondaryLabel、tertiaryLabel、quaternaryLabel 四级。
  • Ant Design：一级文本 88% 不透明度的黑，二级文本 65%，禁用文本 25%。

这两套都是用"半透明的黑"来做灰，而不是固定的灰色值。好处是放在浅灰的底上，它也会相应变深一点，层级关系保持不变：

一级文字（88%）：标题和正文
二级文字（65%）：说明、次要信息
禁用文字（25%）：不能操作的选项
一级文字（88%）：标题和正文
二级文字（65%）：说明、次要信息
禁用文字（25%）：不能操作的选项

注意：分级要同时满足对比度。Ant Design 的文档说，它让正文、标题和背景保持在 7:1 以上（AAA 级）；上面的二级文字在白底上也有约 7:1；禁用文字只有约 1.8:1，但禁用状态本来就不受 4.5 的限制（第 05 节表格下方说过）。至于 iOS 的 secondaryLabel，常被引用的数值是 rgba(60, 60, 67, 0.6)，在白底上约 3.44:1，不到 4.5。不过这个数值来自 iOS 13 时期的资料，苹果没有公开当前的精确取值。

07不要只靠颜色传递信息

一篇 2012 年的同行评审综述统计：欧洲裔男性约 8%、女性约 0.4% 有红绿色觉缺陷；中国和日本男性约 4%～6.5%。也就是说，一个十万男性用户的 App，可能有几千人分不清你的红色和绿色。

08暗色模式

暗色模式不是把颜色反过来。HIG 的原话："这些颜色不一定是浅色版本的反色：很多颜色反转了，有些没有。"它的基本规则是背景变暗、前景变亮，几条要点：

  • 两层背景：iOS 暗色模式有"基础"和"抬升"两套背景色。基础层更暗（接近纯黑），让后面的界面退后；弹出的面板、半屏弹窗用抬升层，稍亮一些，看起来浮在前面。
  • 两种模式都要达标：对比度在深色下同样要满足，自定义颜色必须提供浅色、深色两个版本。
  • 白底图片要压暗一点：带白色背景的图片放在暗色界面里会显得发光，HIG 建议稍微压暗。
  • 不要在 App 里单独做"深色/浅色"开关：用户已经在系统里选过了，HIG 认为 App 自己的开关只会添麻烦，还可能让人以为 App 坏了。

09本课要点

  • 每个颜色都要能说出用途：中性色（大面积）、强调色（只给可点击的地方，一般一个）、语义色（错误、警告、成功）。
  • 同一个颜色不表达两种意思；颜色含义有文化差异（中文股市红涨绿跌）。
  • 按用途命名颜色，用系统语义色（label / secondaryLabel / systemBackground），不在代码里写死色值。
  • 对比度：普通文字 ≥ 4.5:1，大字和图标、边框 ≥ 3:1（WCAG 2.2 AA）。苹果默认的鲜艳色未必达标，要自己算。
  • 文字灰成套分级（iOS 四级，Ant Design 88% / 65% / 25%）。
  • 颜色不能是唯一的信息来源，配上文字、图标或形状；"去色测试"能快速检查。
  • 暗色模式不是反色：背景变暗、前景变亮，弹出层更亮一层；两种模式都要达标，不做 App 内单独的外观开关。
