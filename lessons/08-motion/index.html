动效与反馈

静态的界面讲完了，这一课讲"动起来"的部分：动画多长合适、用什么曲线、为什么苹果偏爱弹簧；有人看动画会头晕，要怎么照顾；还有触感反馈，以及用户等多久会不耐烦。

约 25 分钟 · 纯讲解 · 开了系统"减弱动态效果"时，本页自动播放的动画会停下或换成淡入

01动效是为了说明白，不是为了好看

HIG 动效一章的第一条：有目的地加动效，支撑体验而不是喧宾夺主，不要为了动而动；多余或过度的动画会分散注意力，甚至让人身体不适。几条具体要求：

  • 动效要符合手势和预期。HIG 的例子：从顶部往下拉出来的视图，用户不会想到要往旁边滑才能关掉。
  • 反馈动画要简短、精确。轻快的反馈往往比夸张的动画更能说清信息。
  • 频繁的操作一般不加动画。系统控件已经有很细微的动画；自定义控件如果每点一次都要看一段动画，就是在浪费用户的时间。
  • 动画要能打断。尽量不要让用户等动画播完才能操作，尤其是会反复看到的动画。
  • 动效是可选的。不是每个人都能或都想看动画，所以重要信息不能只靠动画传达，要配合触感、声音等其他方式。

02时长：多数动画在 100～500 毫秒

NN/g 的结论：大多数界面动画应该在 100～500 毫秒之间，而且在不显得突兀的前提下越短越好。

  • 小反馈（勾选框、开关）：约 100 毫秒，感觉是"立刻"。
  • 较大的变化（弹窗出现）：200～300 毫秒。移动距离越长需要越久，大屏上的大幅移动以 400 毫秒为上限。
  • 到 500 毫秒，动画就开始让人觉得拖沓。实际项目里"太慢"比"太快"常见得多。
  • 进场比退场稍长：东西出现时多给一点时间，消失可以快一些。

100 毫秒小反馈
250 毫秒弹窗、页面切换

Material 3 把时长也做成了一张"清单"（和第 1 课的 Design Token 一个思路）：短 50～200 毫秒、中 250～400 毫秒、长 450～600 毫秒、超长 700～1000 毫秒，每档四级。

03曲线：现实里没有匀速运动

同样的时长，速度怎么分配也很关键，这就是缓动曲线。NN/g 的说法：

  • 匀速（linear）看起来不自然，现实中的物体总是有加速、减速。
  • 先快后慢（ease-out）是进场最常用的：一开始就动，显得响应快，最后慢下来，让眼睛跟得上落点。
  • 先慢后快（ease-in）有时用于退场；用在进场会显得反应迟钝，因为刚开始几乎不动。

04弹簧：可以随时被打断的动画

上面的动画都是"固定时长 + 曲线"。苹果的系统动画大多用另一种描述方式：弹簧。从 iOS 17 起，SwiftUI 的默认动画就是一个弹簧（官方文档写明 response 0.55、阻尼 1.0，也就是不回弹）。

弹簧的关键优势是能被打断。SwiftUI 文档的说法：同一个属性上的弹簧动画会被下一个接替，并保留上一个的速度。比如用户把半屏弹窗往上拉到一半又往下拨，弹窗会顺着当时的速度自然转向，而不是突然停住再重新出发。

下面两条跑道，快速连续点"去左边"、"去右边"，对比打断时的样子：

弹簧打断时保留速度，平滑转向
固定时长曲线打断时从零速重新开始

弹簧是本页用物理公式模拟的示意（阻尼比 0.85，有一点回弹），不是 SwiftUI 的原始实现；第二条是 600 毫秒的 ease-in-out。

SwiftUI 里写弹簧只需要两个直观的参数：时长（大致多久停稳）和回弹（0 不回弹，越接近 1 越弹）。系统还给了三个现成的：

withAnimation(.smooth) { ... }   // 平滑，不回弹
withAnimation(.snappy) { ... }   // 利落，轻微回弹
withAnimation(.bouncy) { ... }   // 明显回弹
withAnimation(.spring(duration: 0.4, bounce: 0.2)) { ... }

Material 3 的新版动效令牌里也有弹簧参数（阻尼、刚度）。

05减弱动态效果：有人看动画会晕

HIG 无障碍一章的提醒：快速移动和闪烁的动画用多了会分散注意力、引起头晕，某些情况下甚至会诱发癫痫。容易受影响的人会打开系统的"减弱动态效果"（Reduce Motion）。打开时，App 要减少自动播放和重复的动画，包括缩放和视野边缘的运动。HIG 列出的做法：

  • 把弹簧调"紧"，减少回弹；
  • 让动画直接跟随手势，而不是自己飞；
  • 避免在纵深方向（z 轴）做层级变化的动画；
  • 把平移类的转场换成淡入淡出；
  • 避免从模糊中出现或消失到模糊里。

06触感反馈：用对含义，别用太多

iPhone 能用震动马达做出各种"触感"。开关、滑块、选择器这些系统控件会自动播放触感；自己要加时，HIG 的规定：

  • 按系统定义的含义使用。用户熟悉这些触感，是因为系统在标准控件上一直这么用；含义对不上，就别挪用。
  • 保持一致：同一种操作配同一种触感，用户才能建立因果联系。
  • 配合其他反馈：触感的强弱、软硬要和它伴随的动画匹配。
  • 别用太多：偶尔一次恰到好处，频繁了就烦人。HIG 说最好的触感往往是"用户没意识到，但关掉会想念"。
  • 短触感配离散事件；触感要可以关掉。
类别种类用在
通知成功、警告、错误一个任务或操作的结果，比如存入支票、解锁车辆
撞击轻、中、重、硬、软配合视觉的物理感，比如视图卡到位时轻轻一下
选择选择控件的值正在变化，比如滚动选择器
 
// SwiftUI（iOS 17 起）：值变化时播放对应触感
Button("付款") { pay() }
    .sensoryFeedback(.success, trigger: paidCount)

07等待：多慢算慢

尼尔森（Jakob Nielsen）总结的三道响应时间线，到今天仍是行业通用的参照：

感觉"立刻"
注意到了，思路不断
还在等，但开始走神
去干别的了
00.1 秒1 秒10 秒
0.1 秒内：像直接操控实物，直接显示结果，不需要额外反馈。
1 秒内：用户会察觉延迟，但思路不会断。按钮立刻变成按下或加载的样子就够了。
1～10 秒：要有进度提示。NN/g：2～10 秒用转圈这类循环动画；不到 1 秒不要放转圈，一闪而过反而干扰。
超过 10 秒：用户会去干别的。用显示百分比的进度条，告诉他还要多久，并且给一个取消的办法。

整页加载时，NN/g 推荐用骨架屏：先画出内容的轮廓，再逐步填进真实内容。它适合 10 秒以内的整页加载；单个模块（一张卡片、一个视频）加载时用转圈更合适；上传、下载、文件转换这类过程不适合骨架屏，用进度条。

整页只放一个转圈不知道会出现什么
加载中…
骨架屏先看到页面会长什么样

HIG 对加载的要求也是一致的：尽快显示点什么（什么都不显示，用户会以为 App 出了问题）；能算出进度时用有确定进度的指示器；进度指示器要一直在动，静止不动会被当成卡死；报进度要尽量准确，"5 秒走到 90%，最后 10% 走 5 分钟"会让人觉得被骗。

最后一点提醒：骨架屏、转圈都只是让等待好受一点。NN/g 也说，它们代替不了性能优化。

08本课要点

  • 动效要有目的：说明关系、给出反馈；不为动而动；频繁操作不加动画；动画能打断；重要信息不只靠动画。
  • 时长：多数 100～500 毫秒；小反馈约 100，弹窗 200～300，大幅移动 ≤ 400；500 开始拖沓；进场略长于退场。
  • 曲线：不用匀速；进场用先快后慢（ease-out），退场可用先慢后快。
  • 弹簧可打断、保留速度；SwiftUI 默认动画（iOS 17 起）就是弹簧；用 .smooth / .snappy / .bouncy 或 .spring(duration:bounce:)。
  • 减弱动态效果打开时：平移换淡入淡出、弹簧调紧、不做纵深和模糊动画（HIG）。代码读 accessibilityReduceMotion / prefers-reduced-motion。自动播放超过 5 秒要能暂停（WCAG 2.2.2）。
  • 触感：按系统含义用（通知、撞击、选择），一致、少用、可关。
  • 等待：0.1 秒感觉立刻，1 秒思路不断，10 秒开始走神。2～10 秒转圈，10 秒以上进度条加取消；整页加载用骨架屏。
